# Интеллект NPC: как здесь принимаются решения

## Коротко

В коде **нет правил поведения**. Нет ни одного `if (Hungry) GoEat()`.
Есть внутреннее состояние, есть предложения мира — и есть оценка, из которой
решение **получается само**.

Один и тот же человек в одном и том же положении может поступить по-разному.
Два разных человека в одинаковых обстоятельствах поступят по-разному почти
наверняка. Это не случайность, подмешанная к правилу, — это свойство самой
конструкции.

---

## Почему прежний подход не годился

Было так:

```cpp
if (Hunger > 70)      FindFood();
else if (Energy < 20) Sleep();
else if (Boredom > 0.6) Walk();
```

Здесь решение **уже принято программистом**. NPC лишь опознаёт, в какую
ветку он попал. Отсюда три беды:

1. Поведение предсказуемо до скуки: одинаковое состояние → одинаковый шаг.
2. Мотивов нет. «Идти на работу» — это строчка в таблице, а не желание
   заработать, показать себя и повидать людей.
3. Любая новая возможность требует правки кода интеллекта.

## Как устроено сейчас

### 1. Мир предлагает, человек выбирает

Вещи и места не командуют человеком. Они объявляют, **что они такое**:

```cpp
// Кафе само знает, что оно из себя представляет
AddOffer(EActionType::Eat, TEXT("поесть"), 1200.0f);
AddPromise(ENeedType::Hunger, 0.9f);     // даст сытость
Offers.Last().MoneyCost = 8.0f;          // за деньги
Offers.Last().AvailableFromHour = 7.0f;  // и только днём
```

Это **свойство вещи**, а не правило поведения. Внутри `ACompleteHumanNPC`
нигде не написано, что голодному нужно кафе.

Файлы: `HumanTypes.h` (`FAffordance`, `FNeedPromise`),
`AffordanceComponent.h/.cpp`, `PlaceActor.h/.cpp`, `FurnitureActor.h/.cpp`.

### 2. Оценка

`UDeliberationComponent::Evaluate` взвешивает каждую возможность через
текущее состояние. Двенадцать слагаемых, ни одно из которых не привязано
к конкретному действию:

| Слагаемое | Откуда берётся |
|---|---|
| что это даст | моя нехватка × обещанное, с учётом «сколько влезет» |
| чем кончалось | **выученный** опыт именно с этим местом/человеком |
| любопытство | неизвестность × моя любознательность × скука |
| цена дороги | расстояние × моя усталость и боль |
| цена усилия | требуемое усилие ÷ остаток моей воли |
| страх | опасность × моя тревожность × текущий страх |
| деньги | цена ÷ то, что есть в кармане |
| люди | близость, симпатия, обида, страх, долг |
| замысел | насколько это ведёт к тому, чего я добиваюсь |
| привычка | делал ли я это в такой же час раньше |
| настроение | в подавленности всё блекнет (ангедония) |
| умение | верю ли я, что у меня получится |

Итог — сумма. Никаких веток.

### 3. Выбор — не argmax

```cpp
Weight = Total ^ Sharpness;   // затем взвешенная случайная выборка
```

`Sharpness` падает от усталости, импульсивности и силы чувств. Собранный
человек почти всегда берёт лучшее. Уставший, взвинченный или импульсивный —
как выйдет. Отсюда берётся непредсказуемость **конкретного** поступка при
предсказуемости человека в среднем.

### 4. Опыт выучивается

После каждого дела считается, **что на самом деле изменилось внутри**
(`MeasureOutcome`), и сравнивается с ожиданием:

```cpp
ОшибкаПредсказания = Действительность − Ожидание;
ОжидаемаяЦенность += Ошибка × Скорость;   // MemoryComponent::LearnOutcome
```

Так сами собой появляются «в том кафе вкусно» и «с этим человеком тяжело».
Ключ опыта привязан к **конкретному** месту или человеку, а не к типу
действия: два кафе — два разных опыта.

### 5. Эмоции рождаются из той же ошибки

Ни одного `Sadness += 0.8f`. Вместо этого:

```cpp
Ev.Desirability   = Actual;                    // что со мной случилось
Ev.Unexpectedness = |ОшибкаПредсказания|;      // насколько разошлось с ожиданием
Ev.SelfAgency     = 0.75f;                     // я сам это выбрал
Emotions->Appraise(Ev, Personality);
```

`UEmotionComponent::Appraise` из оценки события выводит конкретные чувства:
неподконтрольная потеря → печаль, чужая вина при ощущении силы → гнев,
она же при беспомощности → страх, своя вина → стыд и вина.

**Пример.** Смерть близкого (`CompleteHumanAI.cpp`, `OnDied`): горе не
назначается. Событие оценивается, а `Desirability` берётся из привязанности.
Кто не был привязан — не горюет. У кого осталась невысказанная обида —
получает вину, потому что «теперь уже не поговорить».

### 6. Пресыщение

Без него человек, нашедший приятное занятие, застрял бы в нём навсегда:
диван честно приносит покой каждый раз. `FOutcomeAssociation::Satiation`
растёт с повтором и тает за несколько часов. Поэтому людям **надоедает** —
и они встают и идут делать другое.

### 7. Замыслы — из хроники, а не из минуты

Голод целью не становится: голодный просто идёт есть.
`UMotivationComponent::FormLongTermAims` смотрит не на текущее значение
потребности, а на то, **сколько времени** её не хватает. Из многодневной
нехватки уважения складывается намерение, которое потом подкрашивает
все решения.

---

## Что осталось не-эмерджентным намеренно

| Место | Почему так и должно быть |
|---|---|
| Рефлекс на боль (`OnHurt`) | При внезапной боли тело действует раньше мысли. Что именно — бей, беги, замри — решает ощущение своей силы. |
| Физика организма (`ApplyNeedEffect`) | Еда наполняет желудок. Это устройство тела, а не решение психики. |
| Свойства вещей (`MakeTypicalFor`) | Кафе кормит, кровать даёт спать. Это знание мира о себе. |
| Часы работы | Ночью контора закрыта. Такой возможности просто нет — человеку не нужно знать «правило». |

## Как добавить новое поведение

**Не трогая код интеллекта.** Поставьте на уровень актор с
`UAffordanceComponent` и опишите, что он предлагает:

```cpp
Affordances->AddOffer(EActionType::Entertain, TEXT("сходить в кино"), 5400.0f);
Affordances->AddPromise(ENeedType::Novelty, 0.7f);
Affordances->AddPromise(ENeedType::Beauty,  0.3f);
Affordances->AddPromise(ENeedType::Money,  -0.1f);
Offers.Last().MoneyCost = 12.0f;
Offers.Last().AvailableFromHour = 12.0f;
Offers.Last().AvailableToHour   = 23.0f;
```

Люди начнут туда ходить — те из них, кому это сейчас нужнее прочего.
Кто-то не пойдёт ни разу: денег жалко или скучно ему не бывает.

## Три ловушки, в которые легко попасть

Всё это было найдено на живых прогонах. Если правите систему — держите
в голове.

**1. Дубликаты вытесняют важное.**
Пять подъездов рядом дают пять одинаковых возможностей «в туалет». Они
заполняли голову целиком, и работа не доходила до взвешивания. Человек
не перебирает «поесть в кафе №1, №2, №3» — он думает «поесть» и идёт
в лучшее. Свёртывание по действию — в `Decide`.

**2. Бесплатное приятное занятие становится ловушкой.**
Диван честно приносит покой каждый раз, и без пресыщения человек ложился
на него навсегда. `Satiation` — не косметика, а условие того, чтобы жизнь
вообще продолжалась.

**3. Случайные места вытесняют нужные.**
Каждая прогулка создавала отметку на карте. Через несколько часов карта
переполнялась, и дорога на работу забывалась — человек переставал
понимать, куда ему идти. Дом и работа теперь защищены от вытеснения,
а случайные закоулки запоминаются только если чем-то зацепили.

**4. Двойной учёт убивает целую сторону жизни.**
Самое дорогое по времени. Никто в городе не ходил на работу. Причина
оказалась не в мотивации, а в арифметике: штраф за неуверенность в навыке
(`(1 − Believed) × 0.5`) давал −0.25, а вся выгода от работы — +0.15.
Работа была обречена в любом состоянии. При этом плохой исход учитывался
уже трижды: в выученном опыте, в частичной раздаче обещанного при провале
и вот здесь. Стало `max(0, 0.6 − Believed) × 0.45` — отпугивает не
«недостаточное умение», а сомнение «скорее не выйдет».

После правки работа сразу вышла на третье место по занятости.

**Как ловить такое.** В `Evaluate` каждое слагаемое печатается отдельно
именно ради этого. Если действие не выбирается никогда — сложите его
слагаемые на бумаге. Если сумма отрицательна при любом мыслимом
состоянии, значит какой-то штраф задан не в том масштабе.

Общее правило: **если поведение пропало — ищите не логику, а поток
данных**. Возможность либо не дошла до оценки, либо утонула в шуме,
либо её задавил непропорциональный штраф.
Для этого в портрете и печатается список взвешенного.

## Замеренные показатели

Городок из 16 человек, один игровой день, без сбоев:

| Занятие | Доля времени |
|---|---|
| дома: еда и отдых | 44% |
| работа | 15% |
| простой («ничего не хочется») | 10% |
| еда вне дома | 7% |
| своё дело, размышления | 8% |
| тело: туалет, питьё, мытьё | 6% |
| прогулки, люди, разговоры | 10% |

Для сравнения, до калибровки: простой 21%, работа 0.7%, а на одном
из ранних прогонов «отдохнуть дома» занимало 37% — человек ложился
на диван и больше не вставал.

```
  дорога -0.00 | усилие -0.00 | страх -0.00 | деньги -0.00 = 0.20

```

Ни одно правило не сработало. Сложились слагаемые.
